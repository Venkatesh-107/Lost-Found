# 🔄 FLOW.md — User Interaction Flows
> **Project:** Lost & Found PWA  
> **Stack:** Vite · Node.js · PocketBase · PWA  
> **Last Updated:** 2026-10-10

---

## 📌 Overview

This document maps all end-to-end **user interaction flows**, **routes**, and **page logic** in the application. It describes the exact steps a user (or system) takes from entry point to completion based on the current implementation.

---

## 🧭 Application Routes

- **`/` (Auth View):** The entry point. Handles login for both Admins and Candidates.
- **`/home` (Candidate Dashboard):** Main interface for regular users. Uses a bottom navigation bar to switch between 4 views:
  - `Home`: The main feed of verified, active found items.
  - `Lost`: A form to submit "Pre-request" Lost Reports.
  - `Tokens`: Displays generated claim tokens for the user.
  - `Profile`: User settings and logout.
- **`/admin` (Admin Dashboard):** Main interface for administration. Uses a top tab bar to switch between views:
  - `Review posts`: A queue of pending found items waiting for admin verification.
  - `All posts`: A list of all live, active posts currently on the public feed.
  - `Claims & tokens`: Queue of tokens generated by users attempting to claim an item.
  - `Lost reports`: A list of pre-request lost items submitted by users.

## Flow 1 — Candidate: Reporting a Found Item

```
[Candidate taps + icon on /home]
        │
        ▼
[Upload Modal opens]
        │
        ▼
[Uploads Image, Category, Sub-Category, Description]
        │
        ▼
[Submit]
        │
        ▼
[Post saved to DB with status='pending']
        │
        ▼
[Admin Review Queue]
```

### Steps:
1. Candidate finds an item and taps the `+` FAB on the `/home` screen.
2. They select an image, choose a **Category** and **Sub-Category** from the taxonomy, and provide a description.
3. The system saves the post to PocketBase with `status = 'pending'`.
4. The post is **hidden** from the public feed until an Admin verifies it.

---

## Flow 2 — Admin: Verifying Found Items & Setting Questions

```
[Admin opens 'Review posts' tab on /admin]
        │
        ▼
[Clicks 'Approve' on a pending post]
        │
        ▼
[Verification Modal opens]
        │
        ▼
[Admin enters the Correct Answers for the item]
        │
        ▼
[Submit]
        │
        ▼
[Post status changes to 'active']
[Answers saved to 'item_questions']
```

### Steps:
1. An Admin logs in and navigates to the **Review posts** tab.
2. The Admin receives the physical found item from the finder and clicks **Approve** on the digital post.
3. A modal appears containing the rule-based verification questions for the item's specific category (e.g. "What is the brand?").
4. The Admin inspects the physical item and enters the **correct answers**.
5. The system publishes the post to the public dashboard (`status='active'`) and saves the correct answers for future claimants to be tested against.

## Flow 3 — Candidate: Pre-Requesting a Lost Item

```
[Candidate loses an item]
        │
        ▼
[Navigates to 'Lost' tab on /home]
        │
        ▼
[Fills out Lost Report Form (Category, Date, Desc)]
        │
        ▼
[Submit]
        │
        ▼
[Report saved to 'lost_reports' collection]
        │
        ▼
[Appears in Admin's 'Lost reports' tab]
```

### Steps:
1. A Candidate realizes they lost an item before anyone has found it.
2. They tap the **Lost** icon in the bottom navigation.
3. They submit a detailed description of what they lost and when.
4. The report is instantly sent to the Admin dashboard under the **Lost reports** tab, allowing the administration to keep an eye out for matching items brought to the desk.

---

## Flow 4 — Candidate: Claiming an Item & Token Generation

```
[Candidate sees their item on /home feed]
        │
        ▼
[Clicks 'Claim']
        │
        ▼
[Answers the verification questions]
        │
        ▼
[Submit]
        │
        ▼
[System validates answers against Admin's correct answers]
        │
        ▼
[Claim Token generated (regardless of pass/fail)]
        │
        ▼
[Candidate takes Token to Admin Desk]
```

### Steps:
1. Candidate browses the public feed and spots their lost item.
2. They click **Claim** and are prompted to answer the verification questions.
3. The system compares their answers to the correct answers set by the Admin in Flow 2 and records a `passed: true/false` flag.
4. **Important Logic:** Regardless of whether the answers perfectly matched, a **Claim Token** is always generated so the candidate is not blocked by typos. 
5. The Candidate takes this token to the administration desk for a final manual review.

---

## Flow 5 — Admin: Investigating & Closing Posts

```
[Candidate presents Claim Token at Admin Desk]
        │
        ▼
[Admin investigates token, answers, and user identity]
        │
        ▼
[Admin approves and distributes physical item]
        │
        ▼
[Admin opens 'All posts' tab on /admin]
        │
        ▼
[Clicks 'Mark Claimed']
        │
        ▼
[Post status changes to 'claimed' and is removed from feed]
```

### Steps:
1. A Candidate arrives at the admin desk with a Claim Token.
2. The Admin manually reviews the token, the candidate's answers, and verifies their identity/worthiness to receive the item.
3. If approved, the Admin hands over the physical product.
4. The Admin finds the post in the **All posts** tab and clicks **Mark Claimed**.
5. The post is officially closed and hidden from the public feed.
